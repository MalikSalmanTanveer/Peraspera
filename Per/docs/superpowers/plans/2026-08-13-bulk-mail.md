# Admin Bulk Mailing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `super_admin` a Bulk Mail screen to paste ≤500 emails, pick an allowlisted From address, optionally load a template, attach one ≤10 MB file, and send via queued Resend batches with progress + per-address results.

**Architecture:** Client parses recipients and creates a job through `admin-api`. Attachment uploads to a private Storage bucket via signed URL. A `processBulkMailJob` worker claims pending recipients in batches of 25, sends individually through Resend (with `from` override + attachment), self-continues until done. UI polls job status.

**Tech Stack:** React 19, TypeScript, Vite, Supabase (Postgres + Storage + Edge `admin-api`), Resend, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-13-bulk-mail-design.md` (T-05)

## Global Constraints

- `super_admin` only for every bulk-mail action and nav item.
- Max **500** valid recipients per job; lowercase + dedupe.
- Exactly **one** optional attachment, max **10 MB**.
- From address must be in allowlist (`BULK_MAIL_FROM_ADDRESSES` env JSON); never free-typed.
- Reuse `career_email_templates` as optional subject/body starters only.
- Batch size **25**; existing hiring `sendMail` stays on env `FROM_EMAIL` unchanged.
- Do not commit unless the user explicitly asks (repo rule — skip Commit steps or leave staged only).
- Match existing admin light UI (`admin-input`, accent buttons, `AdminSelect`).

```ts
export const BULK_MAIL_MAX_RECIPIENTS = 500;
export const BULK_MAIL_MAX_ATTACHMENT_BYTES = 10 * 1024 * 1024;

const EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

export function parseRecipientEmails(raw: string): {
  valid: string[];
  invalid: string[];
  duplicatesRemoved: number;
} {
  const tokens = raw
    .split(/[\s,;]+/)
    .map((t) => t.trim())
    .filter(Boolean);

  const invalid: string[] = [];
  const seen = new Set<string>();
  const valid: string[] = [];
  let duplicatesRemoved = 0;

  for (const token of tokens) {
    const email = token.toLowerCase();
    if (!EMAIL_RE.test(email)) {
      invalid.push(token);
      continue;
    }
    if (seen.has(email)) {
      duplicatesRemoved += 1;
      continue;
    }
    seen.add(email);
    valid.push(email);
  }

  return { valid, invalid, duplicatesRemoved };
}

export function assertBulkMailLimits(
  validCount: number,
  attachmentBytes?: number,
): string | null {
  if (validCount <= 0) return 'At least one valid email is required.';
  if (validCount > BULK_MAIL_MAX_RECIPIENTS) {
    return `At most ${BULK_MAIL_MAX_RECIPIENTS} recipients allowed.`;
  }
  if (
    attachmentBytes != null &&
    attachmentBytes > BULK_MAIL_MAX_ATTACHMENT_BYTES
  ) {
    return 'Attachment must be 10 MB or smaller.';
  }
  return null;
}
```

```sql
create table if not exists public.bulk_mail_jobs (
  id uuid primary key default gen_random_uuid(),
  created_by uuid not null,
  from_email text not null,
  subject text not null,
  body text not null,
  attachment_path text,
  attachment_name text,
  attachment_content_type text,
  status text not null check (status in ('draft', 'queued', 'processing', 'completed', 'failed', 'cancelled')),
  total_count int not null default 0,
  sent_count int not null default 0,
  failed_count int not null default 0,
  error_summary text,
  created_at timestamptz not null default now(),
  started_at timestamptz,
  completed_at timestamptz
);

create table if not exists public.bulk_mail_recipients (
  id uuid primary key default gen_random_uuid(),
  job_id uuid not null references public.bulk_mail_jobs (id) on delete cascade,
  email text not null,
  status text not null check (status in ('pending', 'sent', 'failed', 'skipped')),
  resend_id text,
  error text,
  sent_at timestamptz,
  unique (job_id, email)
);

create index if not exists bulk_mail_recipients_job_status_idx
  on public.bulk_mail_recipients (job_id, status);

alter table public.bulk_mail_jobs enable row level security;
alter table public.bulk_mail_recipients enable row level security;

create policy "No public access bulk_mail_jobs"
  on public.bulk_mail_jobs for all to anon, authenticated
  using (false) with check (false);

create policy "No public access bulk_mail_recipients"
  on public.bulk_mail_recipients for all to anon, authenticated
  using (false) with check (false);

insert into storage.buckets (id, name, public, file_size_limit)
values ('bulk-mail-attachments', 'bulk-mail-attachments', false, 10485760)
on conflict (id) do update set file_size_limit = excluded.file_size_limit;

-- Deny direct client storage access; Edge uses service role
create policy "No public bulk-mail storage"
  on storage.objects for all to anon, authenticated
  using (bucket_id <> 'bulk-mail-attachments')
  with check (bucket_id <> 'bulk-mail-attachments');
```

**From allowlist helper:**

```ts
function getBulkMailFromOptions(): { email: string; label: string }[] {
  const raw = Deno.env.get('BULK_MAIL_FROM_ADDRESSES');
  if (raw) {
    try {
      const parsed = JSON.parse(raw);
      if (Array.isArray(parsed)) {
        return parsed
          .map((x) => ({
            email: String(x.email ?? '').toLowerCase().trim(),
            label: String(x.label ?? x.email ?? '').trim(),
          }))
          .filter((x) => x.email.includes('@'));
      }
    } catch { /* fall through */ }
  }
  return [
    { email: 'contact@peraspera.solutions', label: 'Contact' },
    { email: 'hr@peraspera.solutions', label: 'HR' },
    { email: 'careers@peraspera.solutions', label: 'Careers' },
  ];
}

function isAllowedFrom(email: string): boolean {
  const e = email.toLowerCase().trim();
  return getBulkMailFromOptions().some((o) => o.email === e);
}
```

- [ ] **Step 3: Implement `createBulkMailJob`**

Logic:
1. `requireSuperAdmin`
2. Read `from_email`, `subject`, `body`, `recipients: string[]` (already parsed client-side; re-validate server-side: lowercase, dedupe, EMAIL_RE, max 500)
3. Reject if `!isAllowedFrom(from_email)` or empty subject/body or 0 recipients
4. Insert job `status: 'draft'`, `created_by: authResult.actor.userId`, `total_count`
5. Insert recipients `status: 'pending'`
6. If `has_attachment: true`, create signed upload URL for path `{job.id}/{safeName}` in `bulk-mail-attachments` (upsert), return `{ job, upload: { path, token, signedUrl } }`
7. If no attachment, return `{ job }` (client calls `startBulkMailJob` immediately)

Safe filename: strip path chars; max 120 chars.

- [ ] **Step 4: Implement `startBulkMailJob`**

1. Load job; must be `draft` or `queued`; owned not required beyond super_admin
2. If `attachment_path` expected (`has_attachment` stored via non-null path intent): verify object exists in storage when `attachment_name` set — on create without file, leave path null; client after upload calls start with confirming path already set via `create` returning path that client uploaded to, then `startBulkMailJob` updates `attachment_path`/`attachment_name`/`attachment_content_type` if provided in payload
3. Set `status: 'queued'`, `started_at` if null
4. Fire-and-forget `fetch` to same function URL with `{ action: 'processBulkMailJob', job_id }` using service headers / caller Authorization
5. Return `{ job }`

- [ ] **Step 5: Implement `processBulkMailJob`**

1. Auth: allow `requireSuperAdmin` **or** service-role internal call (same pattern as other privileged actions — use `requireAdmin` + super_admin for manual kick; for self-continue pass admin JWT from kickoff or use service role key in Edge env to update without user JWT). Simplest v1: process endpoint requires super_admin JWT from the kickoff request’s Authorization header forwarded on self-continue.
2. Load job; if `completed`/`failed`/`cancelled` return early
3. Set `processing`
4. Select up to 25 recipients where `status = 'pending'`
5. If attachment_path: download via service role, base64 once per tick
6. For each recipient: `sendResendEmail({ from: job.from_email, to: [email], subject, html: body, attachments })`; update row sent/failed; increment counters
7. If pending remain: self-`fetch` process again; else set `completed` + `completed_at`

- [ ] **Step 6: Implement `listBulkMailJobs` / `getBulkMailJob`**

- list: last 50 jobs order by `created_at desc`
- get: job + recipients where `status = 'failed'` (and optionally all if `include_all: true`)
